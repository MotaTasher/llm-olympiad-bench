# GeoGebra-вьюер решений

Инструмент показывает решение задачи как построение в GeoGebra, разбитое на
шаги: слева текст шагов, справа чертёж, который достраивается по мере движения
вперёд. Нужен, чтобы читать геометрическое решение модели, глядя на картинку, а
не восстанавливая её в голове.

Смотреть сцену можно двумя способами:

- **в scoring-сайте** — панель сбоку от решения на странице задачи. Кнопка
  `Показать построение` появляется, только если для задачи есть сцена;
  состояние панели запоминается. Подробности — в
  [`specs/SCORING_WEB.md`](specs/SCORING_WEB.md);
- **отдельным вьюером** — `scripts/geogebra_view.py`, удобен, когда сцена ещё
  пишется: файл правится, страница обновляется сама.

Оба используют один и тот же движок `scripts/geogebra_viewer/viewer.js`, так
что сцена ведёт себя одинаково.

Вьюер не трогает `logs/`, `data/results/` и никак не связан с прогонами
моделей: это отдельный локальный просмотрщик, работающий только со сценами.

## Запуск

```bash
python scripts/geogebra_view.py scripts/geogebra_viewer/examples/euler_line.json
```

Откроется браузер на `http://127.0.0.1:8770/`. Пока сервер работает, файл сцены
можно править — страница подхватит изменения примерно за секунду, оставаясь на
текущем шаге. Это основной режим: агент правит JSON, вы смотрите результат.

Другие режимы:

```bash
# без файла: пустая сцена, ждёт POST
python scripts/geogebra_view.py --serve

# проверить сцену, ничего не открывая
python scripts/geogebra_view.py scene.json --check

# самодостаточный HTML со встроенной сценой (можно отправить или сохранить)
python scripts/geogebra_view.py scene.json --export /tmp/task_03.html
```

Флаги: `--port` (по умолчанию 8770, при занятости берётся следующий свободный
из десяти), `--host`, `--no-open`.

## HTTP API

| Метод | Путь | Смысл |
| --- | --- | --- |
| `GET` | `/` | страница вьюера |
| `GET` | `/api/scene` | `{version, scene, path?, error?}`; файл перечитывается, если изменился |
| `POST` | `/api/scene` | заменить сцену; тело — JSON сцены |
| `GET` | `/health` | `{"ok": true}` |

```bash
curl -X POST --data-binary @scene.json http://127.0.0.1:8770/api/scene
```

Невалидная сцена в `POST` отклоняется с `400` и списком проблем. Невалидный
файл сцены не роняет сервер: страница показывает ошибку и продолжает
показывать последнюю рабочую сцену.

Отправленная через `POST` сцена держится до следующей правки файла: как только
файл меняется, он снова становится источником.

## Формат сцены

```json
{
  "title": "Задача 3, Gemini 3.1 Pro",
  "source": "logs/math-cup-2026-final/task_03/....json",
  "app": "classic",
  "view": { "axes": false, "grid": false, "labels": "points" },
  "setup": ["A=(0,0)", "B=(8,0)"],
  "steps": [
    {
      "title": "Строим треугольник",
      "text": "Цитата или пересказ соответствующего куска решения.",
      "commands": ["C=(2.4,5.6)", "tri=Polygon(A,B,C)"],
      "highlight": ["tri"]
    }
  ]
}
```

Поля:

| Поле | Смысл |
| --- | --- |
| `title`, `source` | шапка панели; `source` удобно держать путём к логу |
| `app` | `classic` (по умолчанию), `geometry`, `graphing`, `3d`, `suite` |
| `view.axes`, `view.grid` | по умолчанию оба выключены |
| `view.labels` | `points` (по умолчанию), `all`, `none` |
| `view.xmin/xmax/ymin/ymax` | зафиксировать окно вручную; иначе оно подбирается |
| `view.padding` | запас вокруг конструкции при автоподборе, доля (по умолчанию `0.12`) |
| `view.fit` | `"step"` — подбирать окно на каждом шаге по видимым объектам; `false` — не подбирать вообще |
| `view.perspective` | строка перспективы GeoGebra, если нужна не «только графика» |
| `setup` | команды, выполняемые до первого шага и не относящиеся ни к одному шагу |
| `steps[].title`, `steps[].text` | подпись шага и пояснение в панели |
| `steps[].commands` | команды GeoGebra этого шага |
| `steps[].highlight` | имена объектов, выделяемых красным на этом шаге |
| `steps[].view` | своё окно для конкретного шага |

Обязателен только непустой `steps`.

## Как это работает

При переходе на шаг `k` конструкция очищается и заново проигрывается от
`setup` до шага `k`. Поэтому состояние всегда воспроизводимо и не зависит от
того, каким путём вы пришли к шагу. Порядок команд внутри шага сохраняется.

Окно по умолчанию подбирается один раз при загрузке сцены: строится вся
конструкция, по точкам и окружностям считается охватывающий прямоугольник и
расширяется на `padding`. Дальше окно не меняется, поэтому чертёж не прыгает
при перелистывании.

Если сцена подменяет картину целиком (как задача 9 ниже: сначала исходная
конфигурация, потом инвертированная), нужен `"fit": "step"` — тогда окно
считается на каждом шаге по **видимым** объектам. Чертёж будет занимать кадр
целиком, но масштаб между шагами меняется.

Любое окно — заданное вручную или подобранное — расширяется до пропорций
области просмотра, а не растягивается под неё. Иначе масштабы осей разъезжаются
и окружности рисуются эллипсами; это особенно заметно в узкой боковой панели
scoring-сайта.

## Управление

`←`/`→` — шаг назад/вперёд, `Home`/`End` — в начало/конец, пробел —
автопроигрывание. По шагу в панели можно кликнуть. Адрес страницы содержит
`#step=N`, так что на конкретный шаг можно дать ссылку.

## Грабли

- **Нужен интернет.** Апплет грузится с `geogebra.org`; офлайн страница
  останется пустой.
- **`Round(...)` не работает, `round(...)` работает.** Текущая сборка GeoGebra
  отвергает команду `Round` с большой буквы. Проверено на 5.4.920.
- **Скриптовые команды не проверяются.** `SetColor`, `SetLineThickness`,
  `Delete`, `Zoom*` и подобные всегда возвращают «неуспех», поэтому вьюер их не
  контролирует: опечатка в `SetColor` пройдёт молча. Команды построения
  проверяются, и всё непостроенное попадает в красную панель снизу слева.
- **Автоподбор окна считает точки и окружности.** Прямые (бесконечные) и
  тексты, размещённые через `Text(..., (x,y))`, в расчёт не входят и могут
  оказаться за краем — ставьте их внутри области конструкции или задавайте
  `view` вручную.
- **Подписи есть только у точек.** Кривые подписываются явно:
  `SetCaption(w,"ω")`, `SetLabelMode(w,3)`, `ShowLabel(w,true)`.
- **`highlight` меняет цвет и толщину** и действует только на текущем шаге;
  для точек и линий одновременно применяются разные свойства, лишние просто
  игнорируются.

## Где лежат сцены

Сцены по решениям моделей: `data/geogebra/<competition_id>/<problem_id>_<модель>.json`.
Демонстрационные сцены — в `scripts/geogebra_viewer/examples/`.

## Примеры

`scripts/geogebra_viewer/examples/euler_line.json` — прямая Эйлера в шести
шагах: треугольник, центроид, центр описанной окружности, ортоцентр, прямая
через них, окружность девяти точек.

`data/geogebra/math-cup-2026-final/task_09_claude-fable-5.json` — решение
задачи 9 финала 2026 через инверсию, десять шагов. Полезен как образец приёма:
решение живёт в инвертированной картине, где всё считается явно, поэтому сцена
строит именно её по числовым параметрам, а исходную конфигурацию получает
обратной инверсией — `Reflect(<объект>, <окружность>)`. Числа `dd`, `aa`, `cc`,
`hh` в начале `setup` можно менять: остальное считается формулами.

Приёмы, которые там использованы и переносятся на другие решения:

- **строить всё в `setup` и скрывать**, а шагами только показывать нужное
  (`SetVisibleInView(obj,1,true)`). Иначе шаг, меняющий картину целиком,
  пришлось бы собирать заново;
- **своё `view` у шага**, когда картина меняет масштаб (у нас — переход к
  инвертированной картине и обратно);
- **`SetCaption(obj,"X_A")` вместе с `SetLabelMode(obj,3)`** — подпись с
  индексом вместо служебного имени объекта.
